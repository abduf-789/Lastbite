# LastBite — "Every Bite Matters"

A front-end prototype of the LastBite food-rescue marketplace, built in plain
**HTML, CSS and JavaScript** (no build step, no framework) so you can host it
on your own domain immediately.

## Running it

There's no server-side code — it's a static site. Two options:

1. **Just open it.** Double-click `index.html`.
2. **Or serve it** (recommended, so relative links behave exactly like on a
   real host):
   ```
   cd lastbite
   python3 -m http.server 8080
   ```
   then visit `http://localhost:8080`.

To publish it on your domain, upload the whole folder (keeping the `css/`
and `js/` subfolders in place) to your web host and point your domain at
`index.html`.

## What's actually working

This prototype uses your browser's `localStorage` as its "database" — there
is no backend server or real payment/AI/maps API wired up. Everything below
is genuinely interactive, not just a static screen:

- **Explore** (`explore.html`) — search, category and filter chips, sort,
  a live pricing engine that calculates Preventing Sell rescue prices
  (60–70% off, adjusted by time remaining and quantity), a multi-seller
  cart with per-seller minimum-order checks, and checkout that creates
  real order records.
- **Staff dashboard** (`staff.html`) — publish a listing as Normal Sell or
  Preventing Sell, with a live price-calculation preview; manage listings;
  advance order status.
- **Donate** (`donate.html`) — find nearby organizations, submit a donation
  request, and track it through the full status timeline.
- **Delivery** (`delivery.html`) — see jobs generated by orders/donations
  in progress, advance their status, and view mock earnings.
- **Work & Volunteer** (`join.html`) — apply as a delivery partner or
  volunteer, plus a simplified recruiter view to approve/reject applications.
- **Impact** (`impact.html`) — sourced, dated national data (with charts),
  each labelled with its source and methodology, plus a transparent impact
  calculator with stated assumptions.
- **Profile** (`profile.html`) — switch between Consumer and Staff mode on
  one account, see order/donation history and notifications.

## What's intentionally out of scope (marked "Coming soon" in the UI)

A real production build of everything in the original spec — authentication,
a Postgres database, AI image verification, live payments, maps/geolocation,
document storage, a full admin analytics suite — needs an actual backend and
paid APIs. Building that isn't something plain client-side files can do
honestly, so rather than fake it, those areas are either simplified (e.g. a
lightweight recruiter table instead of a full admin console) or explicitly
labelled "Coming soon" per the spec's own instruction not to present
unfinished functionality as if it works.

```
├── donate.html           donation flow
├── staff.html            seller dashboard + pricing engine
├── delivery.html         delivery worker dashboard
├── join.html             delivery/volunteer applications + recruiter view
├── impact.html           food-security data + impact calculator

├── css/styles.css        design system (all styling)

    ├── data.js            mock data, pricing engine, storage layer
    ├── app.js             shared header/footer/cart-drawer/toasts
    └── <page>.js          per-page logic
```

## Swapping in a real backend later

Every page calls into `LB.api.*` (defined in `js/data.js`) instead of
touching `localStorage` directly — `getListings()`, `addToCart()`,
`createDonation()`, and so on. To connect a real backend, replace the
bodies of those functions with `fetch()` calls to your API; the pages
themselves don't need to change.

## Fonts & images

The design uses Google Fonts (Fraunces, Plus Jakarta Sans, IBM Plex Mono)
and Unsplash-hosted placeholder food photos, loaded from their CDNs — both
need an internet connection, which your live domain will have.
